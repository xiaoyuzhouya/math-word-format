# math-word-format · 数学文档 Word 排版规范化

> 一个 WorkBuddy 技能：把数学类 Word 文档统一成规范排版，并把正文里的**裸数学符号变成真正的 Word 公式对象**。
>
> A WorkBuddy Skill that normalizes math-related Word documents and converts bare math symbols into real Word equation objects.

---

## 它解决什么问题

数学老师、教研员、编辑在 Word 里排版时，反复被同一批问题折磨：

| 常见毛病 | 本技能怎么处理 |
|---|---|
| 公式里数字和括号被拉成斜体 | 按字符属性拆分：变量斜体、数字/括号/运算符正体 |
| 正文里的 `x`、`S(a)`、`|x−a|`、`x₄` 是普通文本，不是公式 | 转成真正的 Word 公式对象（OMML），可再编辑 |
| 上下角标不对（`x1` 应为 `x₁`） | 生成 `m:sSub` / `m:sSup` 正确的上下标 |
| 句末混用全角「。」、式子内用 `…` | 统一为半角 `.`、式子用 `⋯`、文中用 `…`、减号用 `−`(U+2212) |
| 列表前是难看的黑点 | 改为实文字序号，首行缩进 2 字符、第二行顶格 |
| 图片跑到下一页、图题和图片分离 | `keepNext` / `keepLines` 锁定图与图题同页 |
| 行距设成固定值，高公式和大图被裁掉 | 图片段单倍行距、含公式段最小值 22 磅、纯文字段固定 22 磅 |
| 标题、正文、表格各处字号不统一 | 一份固化 CSS 规范统一口径（含三线表五号字） |

**关键认知**：CSS 只能管版式，**管不到字符**。公式斜不斜、句末是全角还是半角、题号缩进多少，这些都写在 docx 的 XML 里，必须用 OOXML 手段处理。

## 目录结构

```
math-word-format/
├── SKILL.md                        # 技能主文件：开工闸门 → 工作流 → 硬规则速查
├── assets/
│   └── math-word.css               # 排版规范本体（15 节）：字号/行距/五级标题/三线表/公式字符属性
├── references/
│   ├── word-setup.md               # CSS 管不到、必须在 Word 里手做的设置清单
│   ├── ooxml-cookbook.md           # OOXML 改造口径与实测踩坑（动手前必读）
│   └── qa-checklist.md             # 交付前逐项验收清单（结构层 + 渲染层 + 内容层）
└── scripts/
    ├── docx_probe.py               # 结构审计 + 体检项
    ├── docx_textdiff.py            # 全文逐字比对，证明「只搬符号未改字」
    ├── docx_patch.py               # OOXML 原子改造引擎（含 OMML 公式生成器）
    ├── render_check.py             # PDF 逐页渲染 + 空白检测 + 字节对照
    └── word_export_pdf.ps1         # 调用本机 Word 导出 PDF（内置安全约束）
```

## 使用

**触发方式**——当你说这些话时会自动启用：

- 「用这个 CSS 统一格式」
- 「按数学 Word 规范排版这份 docx」
- 「把公式做成公式对象」
- 「数学文档规范化」「公式显示不正常」「数字和括号斜了」「图片显示不全」「角标不对」「有黑点」

**前置条件**

- Python 3.10 及以上，仅用标准库即可完成审计 / 比对 / 原子改造；
- 逐页渲染复核需安装 **PyMuPDF**；
- 若要跑 Word 实测 / 导出 PDF，本机需安装 **Word 或 WPS**。

**典型流程**

1. **结构体检** —— `docx_probe.py` 一次性拿到部件清单、段落/表格/图片/公式计数、属性分布、标点统计与体检项。
2. **决定路线** —— 从零排版走「HTML + `math-word.css` → 另存 docx」；改造既有 docx 走 OOXML 原子改造。
3. **原子改造** —— `docx_patch.py`：先备份 → 精确锚点替换（不用全文正则，避免误伤 `Canvas 2D`、`#2c3e50` 这类非数学内容）→ 每次改动做「文本不变」断言。
4. **双重验收** —— 本机 Word 导出 PDF + 逐页渲染，**亲眼核对**改动页；未改动页的渲染字节数必须逐张相同。

## 安全声明

- **全程本地运行，不访问网络，不上传任何文档内容。**
- 脚本只操作调用者指定的 docx，不改系统设置、不写注册表。
- 破坏性操作前**一律先备份**；写回采用原子方式；「文本不变」断言失败即中止。
- `word_export_pdf.ps1` 内置硬约束：**绝不退出用户的 Word/WPS，绝不触碰用户已打开的文档**，目标文件被占用时自动中止并报告。
